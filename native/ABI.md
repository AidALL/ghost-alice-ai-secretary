# Native transport ABI

Both helpers consume one bounded JSON request on stdin and emit one JSON response. The builtin helper is independent; the optional product links only PeekabooAutomationKit and PeekabooFoundation. `backend` is `builtin` or `peekaboo`; a helper refuses a mismatching selection. Status reports its actual backend, version and capabilities. `actual_input_qualified:false` records the remaining fixture qualification, not compile compatibility.

All effects require `_authorization:{payload,token}`. `payload` is base64 of the exact UTF-8 JSON bytes (maximum 16 KiB); `token` is lowercase hex HMAC-SHA256 of those bytes using the private 32-byte native observation key. HMAC covers raw bytes, so Python/Swift JSON canonicalization does not cross this boundary. The server rejects caller-supplied private fields, constructs this envelope and inherits its exclusive lock FD via `pass_fds`.

The payload has exactly: `db_path,run_id,session,admission_id,task_id,input_event_id,lifecycle_id,epoch,run_fence,operation_id,attempt_id,lease_owner,lease_fence,lease_boot_id,dispatch_lock_fd`. Counters and FD are positive JSON integers. DB and lock are owned private regular files. The lock is exactly `desktop-dispatch.lock` under the mode-700 DB directory. The native process verifies the inherited inode/path and contention from another open description, duplicates the descriptor, and never issues LOCK_UN. Parent ownership remains held until quiescence and confirmed child reaping. A lease timeout does not release this OS lock.

Final read-only SQL validation requires active exact `execution_contexts` identity, matching enabled Running lifecycle epoch, `execution_operations` exact operation/run/attempt link, Applying operation/current attempt/task, context desktop fence and lease owner/fence/current boot/unexpired `mach_absolute_time` clock. The existing private database is opened without CREATE and with filesystem write access for SQLite WAL coordination; `PRAGMA query_only=ON` is set and read back before BEGIN, preventing authority row/schema changes. This permits WAL/SHM initialization when the last store connection removed those files. No immutable, nolock or copied database is used. SQLite closes before input or async UI service calls. The check occurs after target/focus/corroboration and before crossing the effect boundary. Cancellation racing after native acceptance can still require Unknown reconciliation.

Every context also requires the exact current `execution_admissions` mirror for its session/admission/task/input. A still-Active context created from an older gate sample cannot dispatch after the durable admission mirror changes or disappears. The mirror joins the same final read snapshot as lifecycle, operation and ownership checks.

If `authority_runs` contains the context's collection run, that same read snapshot also requires Running/Pending exact lifecycle/epoch/run fence, an unrevoked current source revision/active run/fence, and an unrevoked unexpired grant with matching source revision, scope digest and admission lineage. An unresolved retrieval must belong to this exact run and operation and be Applying/Unknown/Pending. A generic context without a collection row skips these collection predicates.

`observe` may accept the same private context. An effect-ready observation includes signed `backend` and `ownership`: all payload identity fields except DB path, boot receipt and descriptor. This includes operation/attempt. The server must freshly observe under the current Applying operation and retained desktop ownership. Reusing/relabeling old ownership is refused. Plain read-only observations are target data and cannot dispatch effects.

Selectors live inside the signed observation as `selectors:{schema:"secretary-selectors-v1",refs,truncated}`. Maximum encoded size is 256 KiB; at most 128 refs; each string is at most 4096 UTF-8 bytes. Each ref has exactly `ref,role,identifier,label,geometry,enabled,actionable,visible`. Reference IDs are opaque invocation data. Click accepts `element_ref` and excludes caller x/y when it is present. Fresh exact-window AX inspection must be complete and contain one identical role/identifier/label/bounds descriptor, both enabled/actionable/visible. Changed, duplicate, missing, truncated and unknown-schema evidence refuses. Window-contained geometry establishes selector visibility; the existing point occlusion check also runs immediately before dispatch. This is target corroboration, not element-incarnation or application-semantic proof.

The builtin AX adapter dynamically resolves `_AXUIElementGetWindow`, the same exact-ID seam used by the selected upstream library. It requires one AX window with the signed CGWindowID and matching bounds; missing mapping, duplicate mappings and changed bounds refuse. Focused-window keyboard guards also require that exact ID. `ax_window_id_binding_available` is reported in status; when unavailable, selector-click/focus/type/hotkey are omitted from the capability list. This private seam still requires the root's actual fixture qualification. Status/apps/windows remain read-only and do not use AX window binding.

The builtin tree extractor marks every omitted child from depth, child-count or total-node budgets as incomplete, including read failures. Exact boundary trees can remain complete when nothing was omitted. It retains complete strings up to 4096 UTF-8 bytes and emits an incomplete flag for oversized strings; it never corroborates selectors from shortened label prefixes.

Observation publication captures the process generation before inspection and pins the first selected CGWindowID for capture and final window rereads. Reordering another same-geometry window cannot replace that target. The final window must retain its ID, owner and bounds, original result/capture metadata must retain the initial ID, and the generation must remain unchanged before signing. Capture also checks that ScreenCaptureKit's selected window belongs to the pinned PID/current generation. Missing initial windows and reused process generations refuse publication.

The optional helper constructs a private in-memory snapshot manager, noop feedback client and injected lane coordinator under `native-coordination` beside the DB. Its click always uses coordinates, `snapshotId:nil`, the exact window/process generation receipt and `allowsAccessibilityValueDelivery:false`. No fuzzy element resolver, shared host, upstream authorization, default effect constructor or global fallback is selected. The optional backend implements exact-window click/type/hotkey; Secretary's own guarded focus/open remain available. Drag and point scroll are builtin capabilities only.

The absorbed ClickService has one additional disclosed patch: the false AX-value flag propagates into its synthetic destination and selects the existing WindowRoutedPointerDriver for single/double/right clicks. The original single-left "synthetic" route wrote AXFocused/AXSelected despite that flag. The selected route now posts native events addressed to the exact PID/window, validates the process generation/window/bounds at event boundaries, and never retries through AX or global input. AppKit/WebKit uses public PID event posting with a private window-location stamp; Catalyst/Chromium/Electron selects upstream SkyLight PID posting. These platform seams require actual fixture qualification. Literal typing with synthOnly uses process-targeted Unicode keyboard events and exact-window focused-element validation; it does not write AXValue.

`backend_outcome` preserves upstream dispatch evidence and target identity where returned. Refusal is `not_started`; partial, indeterminate, dispatched-unverified and untyped post-boundary errors are `unknown`. Native success never proves that a message sent or a file downloaded. No automatic backend retry may follow a possibly started effect.

Builds do not install or activate a helper. Distributions must include `THIRD_PARTY_NOTICES.md` and `Notices/`; optional builds require the exact transitive lock and verified absorbed sources. The test window is built only with `--test-window`, and is never installed by the build script.
